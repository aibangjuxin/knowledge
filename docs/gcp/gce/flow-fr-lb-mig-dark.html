Why Backend Service is the focal point

Every HTTPS LB chain funnels into one Backend Service. It holds the balancing mode, session affinity, Cloud Armor policy, the binding to MIGs or NEGs, and the live health of every backend. Strip any other component and traffic breaks; strip this one and there is no load balancing.

Health check is off the data path

  • GCP probe ranges 35.191.0.0/16 & 130.211.0.0/22 hit VMs on TCP/HTTP/HTTPS
  • Only the Backend Service reads the result — FR, Proxy, URL Map never see probes
  • Unhealthy VMs are pulled from the dispatch pool, not the LB chain

Why the chain order matters

  • Forwarding Rule pins IP & port
  • Target Proxy unwraps TLS
  • URL Map picks a Backend Service by host / path
  • Backend Service picks a healthy VM
  • gcloud rejects out-of-order dependencies
