THE HEADLINE

Backend Service is the dispatch hub

Every Global HTTPS Load Balancer chain funnels into one Backend Service. It holds the balancing mode, session affinity, Cloud Armor policy, the binding to one or more MIGs or NEGs, and the live health of every backend. Strip any other component and traffic breaks; strip this one and there is no load balancing.

Health checks are off the data path

  • GCP probe ranges 35.191.0.0/16 & 130.211.0.0/22 hit VMs on TCP/HTTP/HTTPS
  • Only the Backend Service reads the result; FR / Proxy / URL Map never see probes
  • Unhealthy VMs are taken out of the dispatch pool, not the LB chain

Why the chain order matters

FR pins IP and port. Proxy unwraps TLS. URL Map chooses a Backend Service by host / path. Backend Service picks a healthy VM. Each object is created and referenced left-to-right — gcloud rejects out-of-order dependencies.
