ADR-009 · GKE Pod 挂载公司内部 NAS — 架构总览

\\\\nas.address.aibang\\hk\\gsd\\application\ · 4 视角:网络链路 / 横向访问面 / 多租户隔离 / 审计链

① 网络链路 — SMB over TCP 445 走 Cloud VPN tunnel

GKE Pod 在 VPC 内,公司 NAS 在公司内网,两端跨网络边界;必须经 IPsec VPN,不允许 SMB 直连公网。

GKE Pod / Node
PV / PVC
Cloud VPN / Network
公司侧边界 / 禁止路径
SMB 流量 (TCP 445)

② 横向访问面 — NetworkPolicy 是关键防线

默认 K8s egress 是 allow-all;同 namespace 其他 Pod 都能直打 NAS。配 NetworkPolicy 后,只有带标签的 API Pod 能出栈。

③ 多租户隔离 — 既有 PV 设计对 NAS 完全失效

CMEK / labels / Tenant CRD.scAllowlist 对 NAS 都不生效;NAS 必须独立治理。

④ 审计链 — GKE 侧和 NAS 侧审计是断的

Pod 读 NAS 的文件级事件不会出现在 GKE audit log;NAS event log 不会带 K8s namespace/Pod 信息。两边只能靠时间戳 + CIDR 手工关联。

主路径 (A) — NAS 原状加固

  • • Cloud VPN tunnel + SMB CSI driver + NetworkPolicy
  • • 业务方接受 read-only 优先
  • • 接受 NAS 不在 PV 多租户体系内
  • • 实施清单 8 项,交 infra-gcp

替代 (B) — GCP Filestore (NFS)

  • • 免 VPN,免 SMB CSI driver
  • • 走回 PV 体系,CMEK/labels 全覆盖
  • • 数据需迁移(同步策略待评估)
  • • 何时推:NAS 数据可迁移、延迟敏感

替代 (C) — NetApp Volumes (SMB)

  • • SMB 协议,业务侧零代码改动
  • • 企业级 ONTAP,部分区域未 GA
  • • 数据需迁移,成本高于 Filestore
  • • 何时推:强需求 SMB + 数据可迁移

禁用方案

  • • ❌ NAS 直连公网 (端口转发)
  • • ❌ 整个 namespace 共享 PVC
  • • ❌ privileged + hostPath 旁路
  • • ❌ NAS 凭据写在 manifest env
