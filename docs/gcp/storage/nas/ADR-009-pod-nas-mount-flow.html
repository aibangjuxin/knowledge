业务方写 Pod manifest 时,只接触 L1 + L2,中间 4 层(L3-PV / L4-CSI / L5-协议 / L6-存储)由平台 + 协议自动处理。

③ PSC 位置 —— 在哪 / 不在哪

挂 NAS 跟 PSC 没关系;PSC 用于访问 GCP 托管服务(如 Cloud SQL),不适用于公司内网 SMB。

④ 决策树 —— 何时用 NAS,何时用 Filestore,何时用 PSC

三种路径适用场景完全不同,业务方根据数据迁移意愿 + 协议偏好 + 多租户需求选择。

核心结论

  • • 挂 NAS = 6 层抽象 + 1 条 SMB 数据通路
  • • PSC = GCP 内部私有访问机制
  • • 两者完全无关
  • • 业务方只接触 L1 (Pod) + L2 (PVC)
  • • 中间 4 层由平台 + 协议自动处理

业务方 FAQ

  • • NAS 跟 PV 是什么关系?PV = K8s 抽象,跟"什么存储"无关
  • • NAS 跟 PSC 是什么关系?❌ 没关系
  • • 数据会经过 GCP 吗?❌ 不会
  • • 跟 Filestore 区别?Filestore 在 GCP VPC 内
  • • Pod spec 要写 NAS 地址吗?❌ 不需要
