approve-tenant-project.sh — Producer-side PSC Approval Flow

Run in Producer (master) project · ACCEPT_MANUAL mode · 6-section orchestration loop

Why SA-side state, not NEG-side

  • Producer cannot read tenant's pscConnectionStatus directly
  • Producer reads SA.connectedEndpoints as a mirror
  • consumerAcceptLists = truth source; connectedEndpoints = 30s-delayed reality
  • Reverse audit: tenant-side NEG describe shows pscConnectionId

Two-mode approval (jq merge)

  • Read current list via jq '.consumerAcceptLists[]'
  • Filter out the tenant (idempotent re-approve)
  • Append new entry tenant=N with limit
  • gcloud update --consumer-accept-list=merged (full replace, no add-only API)

Wait + verify loop

  • Default: -w 30 seconds, -m 3 retries (90s total)
  • Poll SA.connectedEndpoints[X].pscConnectionStatus
  • ACCEPTED → ok · PENDING/NOT_FOUND → retry · REJECTED/CLOSED → abort
  • If not yet propagated after 90s: warn but don't fail (tenant NEG may not exist yet)

Hard limits & gotchas

  • ACCEPT_AUTOMATIC mode → script exits early (nothing to approve)
  • -n (non-interactive) requires -a -r AND -t or -f
  • Producer cannot auto-discover pending tenant NEGs (GCP control plane limitation)
  • REJECTED → check consumer-reject-list + tenant NEG's psc-target-service URI + region match
