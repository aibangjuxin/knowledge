GKE NEG Finalizer 阻塞链路

Namespace 为何卡在 Terminating  ·  networking.gke.io/neg-finalizer 如何把 K8s 对象删除绑定到 GCE 资源删除

NEG 的「特殊设置」到底是什么

  • • 在 Namespace 内建 CRD ServiceNetworkEndpointGroup（SvcNeg），status-only
  • • 创建时即打上 finalizer networking.gke.io/neg-finalizer
  • • 语义 = 「GCE 侧 NEG 删成功，才放行这个 CR 删」
  • • 所以 Namespace 不是被禁止删除，而是被顺延了

卡死的唯一真凶

  • • 官方：NEG 被 backend service 引用时 不会被 GC
  • • Compute API 硬规则：NEG 作为 backend 时不可删除
  • • 源码：deleteNegOrReportErr 失败只发 Event、返回 false
  • • shouldDeleteNegCR = false → 不清 finalizer → 无限重试，无放弃上限

慢 vs 卡死：怎么区分

  • • 正常延迟：几分钟到十几分钟，最终自己消失 = GC 周期（~2min/轮）
  • • 永久卡死：几小时/几天不消失 = GCE NEG 删不掉
  • • 决定性检查：kubectl get svcneg -n <ns> -o yaml 看有无 NegCRError 事件
  • • kubectl get all 看不到 SvcNeg（它是 CRD）

根治手段（架构层）

  • • 不逐个解 finalizer，而是把拆除顺序写进 IaC teardown
  • • 正确顺序：拆 backend service 引用 → 删 Service/Ingress → 最后删 Namespace
  • • 适用 Ingress 托管 / standalone 手工 / 跨项目全部三类引用方
  • • 不涉及任何集群策略，纯编排层改造
