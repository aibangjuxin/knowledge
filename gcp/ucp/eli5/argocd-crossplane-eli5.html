Git 里写一行 YAML，怎么就变成了真的云集群？

Argo CD 和 Crossplane 一起工作的样子 · 像讲给五岁小孩

先说最重要的

Argo CD 和 Crossplane 之间，没有任何一根电话线。

它们俩谁也不认识谁。它们只是碰巧写同一个地方。

① 有人按下按钮

开发者
写 YAML
→
Git 仓库
像大柜子

YAML 是一张“申请书”：我要一个 3 节点、在新加坡的 GKE 集群。

② 快递员（Argo CD）

Argo CD 盯着 Git。看到新提交，它把 YAML 抄成一个真的东西，放进 Kubernetes 这个“公共储物间”。

公共储物间的正式名字：K8s API Server。抄出来的东西叫 XR。

③ 公共储物间是唯一总线

Argo CD 写 XR，Crossplane 读 XR。它俩靠“储物间的门响了一声”来通信。

④ 翻译官拆成两份

XR：GKECluster
大申请书
MR：Cluster + NodePool
细碎工单

Crossplane 把大申请书拆成两张工单，再派工人去 GCP 真建。

⑤ 反过来看：谁能改？谁记账？

能改的：只改 Git 里的 YAML，再提 PR。别的都不算数。
写 spec 的：Argo CD。写 status 的：Crossplane。分工天生不打架。
记账的：每个 XR 的 status 里都有“Synced / Ready”，云上也真的建成了。
