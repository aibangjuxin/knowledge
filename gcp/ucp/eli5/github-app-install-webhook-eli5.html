我把 App 装上了，它怎么还没干活？

注册 → 安装 → 部署 → 拦住合并 · 讲给五岁小孩

先回答

装好 App，不会自动开始工作。要三样同时到位：GitHub 上的 App、你服务器上的后端、仓库的合并规则。

App 是两半

GitHub 那半是一份证件：能读什么、能写什么、往哪儿送信。你那半是常驻的服务器程序，只有它收到信才会干活。点 Install 只是把证件交给你。

代码怎么变成会跑的服务

Git 里有一份代码，不等于有服务在跑。要 CI 造镜像、合进 main、Argo CD 部署、Pod 起来，Ingress 再给一个公网 HTTPS 地址——你填的 Webhook URL 就是它。

有人提 PR 的那一刻

Webhook 就是 GitHub 主动发来的一次网络请求（它来敲你的门，不是你去问它）。你的服务验签、读 PR、跑规则，再写一个检查结果（Check Run）回去。

拦住合并的三层

写出检查 ≠ 拦住合并。要仓库规则（Branch Protection / Ruleset）把那个检查列进必须通过（required status check），GitHub 才真的不放行——而且名字必须一模一样。

出事的时候

后端挂了会怎样？检查就永远不绿，所有 PR 被卡住（fail-closed：门宁可关太严，也不会漏）。所以先只记录、再只报告、最后才开强制，并留一个能临时放行的口子。谁能改？App 的安装者、仓库规则管理员。
