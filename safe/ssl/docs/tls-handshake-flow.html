TLS Handshake — Message Flow

TLS 1.2 (2-RTT) vs TLS 1.3 (1-RTT) — what crosses the wire, in order

TLS 1.2 — what you used until ~2018

  • • 2 round trips before any application byte — the server doesn't even know the secret until ClientKeyExchange arrives
  • • Certificate, ServerKeyExchange, ServerHelloDone all cleartext — passive observers see server identity + cert chain
  • • Cipher suites are giant blobs: TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256 — KEX + auth + AEAD + hash all named together
  • • Optional RSA key transport (no forward secrecy) — most modern stacks force (EC)DHE but the protocol still permits it
  • • ChangeCipherSpec is a record-layer wart, not a real handshake message

TLS 1.3 — RFC 8446 (2018)

  • • 1 round trip — client guesses the ECDHE group and sends its key_share in the very first ClientHello
  • • Everything after ServerHello is encrypted: certificate, CertVerify, Finished, plus a new EncryptedExtensions
  • • Static RSA removed — every public-key KEX now provides forward secrecy. Server picks its own DH params from the client's offered shares
  • • Cipher suite = only the AEAD + hash (e.g. TLS_AES_128_GCM_SHA256). Auth + KEX negotiated independently
  • • Optional 0-RTT: client can ship application data on the first flight using a PSK from a previous handshake (with replay caveat)

Common pitfalls + verify commands

  • • openssl s_client -connect host:443 — see negotiated version + cipher; Protocol: TLSv1.3 + Cipher: TLS_AES_128_GCM_SHA256 is the modern line
  • • verify error:num=20 — client trust store is missing the server's root CA; fix with -CAfile or update the OS bundle
  • • verify error:num=21 — server didn't ship the intermediate chain (common in self-hosted setups); fix server config, not the client
  • • 0-RTT + non-idempotent POST = replay risk; only enable 0-RTT for GETs, or use single-use tickets with freshness checks
  • • TLS 1.0/1.1 deprecated by all major browsers since 2020; modern servers should fail handshake if client insists
  • • Verify with openssl s_client -tls1_2 / -tls1_3 to test each version individually during a server cutover
